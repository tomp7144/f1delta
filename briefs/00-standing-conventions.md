# F1 Delta — Standing Conventions

Cross-cutting rules that apply across briefs and must not be forgotten as the site grows. Not tied to any single feature — these are permanent working principles. Check this before shipping any brief that adds a page type or touches search.

---

## SEARCH

### RULE S1 — Every new page type must be added to the search index (as part of building it)
`public/search-index.json` is generated by `derive-search.mjs`, which reads the site's entity types. **Search can only return what's in that index.** Therefore:

> **Any brief that creates a new type of page MUST include, as an explicit step, updating `derive-search.mjs` to index that new type — with its label, type/group, URL, and matchable fields.**

If this step is skipped, the new pages are invisible to search (like the homepage-search 404 we hit after deleting `/api/driver`). "Build it, then remember search later" is banned. New entity type → index it in the same cluster.

**Applies immediately to:**
- **Brief 08 race pages cluster** — the ~1,500 individual race pages MUST be added to `derive-search.mjs` (new group: "Races," e.g. label "2016 Malaysian Grand Prix", url `/races/...`, matchable on year + GP name + circuit + country). This is a required step in the race-pages BUILD brief, not optional.
- Any future page type (driver comparisons, articles, etc.) — same rule.

### RULE S2 — Search matching must handle multi-word, word-order-independent queries
Real queries are typed loosely: "malaysia 2016", "2016 malaysia", "hamilton 2016". Current matching is word-*prefix* against the label in label order, which may miss reordered / partial multi-word queries.

> **Search scoring must match all query words against the entry regardless of order** (e.g. "malaysia 2016" matches "2016 Malaysian Grand Prix"), and handle stem-ish cases like "malaysia" vs "malaysian".

**Status:** folded into the **search ranking-tuning pass** (the planned follow-up to Brief 07). Must be verified with multi-word race queries once race pages exist.

## URLS / SEO

### RULE U1 — Lock URL structure before generating pages at scale
Changing a URL pattern after pages exist means a redirect migration (we lived this: `/driver` → `/drivers`). For any page type generated in bulk, **decide and lock the URL/slug structure in the read/plan brief before the build brief generates anything.** (Brief 08 does this for race pages.)

### RULE U2 — Bulk page moves require 301 redirects + sitemap update + internal-link sweep
If a URL pattern ever changes: 301 every old URL to new (edge function pattern from the SPA fold works cleanly and drops query strings), update the relevant sitemap, and sweep internal links. Never leave old URLs 404ing.

## WORKFLOW (from the working agreement)

### RULE W1 — Push is the owner's step, every brief
Cody commits; owner reviews and pushes. Every brief states explicitly whether it ends in a push. Committed ≠ deployed — Netlify only serves pushed commits.

### RULE W2 — Verify deployed before debugging behavior
Confirm a change is actually live (git status + fresh load / curl) before diagnosing why it "isn't working." Multiple detours came from debugging stale or unpushed code.

### RULE W3 — Read before prescribing; one verified brief at a time
Read the actual code/data before scoping changes. Big features are clusters of sequenced, individually-verified briefs — not one mega-brief. No easy-subset shortcuts; build the right version, sequenced.

### RULE W4 — Numbered briefs, two digits (`01`, `02` … `10`, `11`)
So they sort correctly in the briefs folder.

## DATA INTEGRITY

### RULE D1 — Never state numeric/data facts from memory as confirmed
Race counts, dates, stats come from the repo, the data, or a verified check — not assumption. Flag inference vs. confirmed fact.

### RULE D2 — Nothing is gated
Pro is removed. No content is gated. The payment stack (Stripe/Blobs/access module) is preserved only for the future "Go Ad-Free" (paid ad removal) feature — not for gating content.
